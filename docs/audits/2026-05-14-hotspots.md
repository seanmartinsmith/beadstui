## Scoring Methodology

- **MaxCyclo**: highest cyclomatic complexity (McCabe CCX) among all functions in the file.
  Values from gocyclo violations > 30; files with no function exceeding 30 show 0.
- **MaxCogn**: highest cognitive complexity among all functions in the file.
  Values from gocognit violations > 30; same floor applies.
- **Churn90d**: number of commits touching this file in the 90 days prior to the audit SHA.
- **Score**: `MaxCyclo * Churn90d`. Used for ranking. Files with MaxCyclo=0 (no function
  exceeds CCX 30) are listed separately below by churn alone.
- Test files (`*_test.go`) are in a separate table.
- Vendor files excluded entirely.

## Calibration Notes for bt-8s9

Suggested thresholds based on this baseline:

- **gocyclo gate**: `--min-complexity 40`. This catches the Tier 1 pathological cases
  (294, 101, 98, 90) while excluding the structurally-acceptable dispatchers (42-65 range
  in `model.go`, `history_keys.go`). Current above-30 count: 43 violations.
- **gocognit gate**: `--min-complexity 80`. Above-30 count is 138 violations, too noisy for
  a hard gate. Setting at 80 narrows to 15 violations that represent genuine outliers.
- **Alternative**: Use golangci-lint with per-linter overrides in `.golangci.yml`; skip
  files with `//nolint` annotations that carry bead references.

These thresholds should be re-evaluated after the Tier 1 refactors ship. The goal is
to gate against the `handleKeyPress`/`handleFileChanged` class of growth, not to flag
every complex-but-stable algorithm.
